# Verification

The Rust port was compared with the official Python package **`vieneu`
3.8.3** (its CPU / ONNX Runtime path, with `sea-g2p` 0.10.0) on a 4-core
machine in October 2026, using the model commits the crate pins (see
`src/turbo.rs`, `src/nano.rs`). Every script, input and output is in this
folder.

## 1. Phonemes (sea-g2p): identical

- Input: [`g2p_sentences.txt`](g2p_sentences.txt) (numbers, dates, e-mail,
  English words, °C, %, quotes).
- Python: `SEAPipeline(lang="vi").run(line, punc_norm=True)` →
  [`results/g2p_python.txt`](results/g2p_python.txt)
- Rust: test `phonemize_lines` → [`results/g2p_rust.txt`](results/g2p_rust.txt)
- `diff`: no difference.

```sh
VIENEU_TEST_DICT=models/vieneu-tts-v3-turbo/sea_g2p.bin VIENEU_TEST_TEXTS=verification/g2p_sentences.txt \
  cargo test --release phonemize_lines -- --ignored --nocapture
```

## 2. Turbo tokenizer: identical

The phonemes above through Turbo's `tokenizer.json`: Python `tokenizers` →
[`results/tokens_python.txt`](results/tokens_python.txt), Rust (test
`tokenize_lines`) → [`results/tokens_rust.txt`](results/tokens_rust.txt).
Identical.

## 3. Turbo with sampling off: the same audio codes

With `temperature = 0` (the repetition penalty still on), the same
phonemes ([`results/turbo_greedy_phonemes.txt`](results/turbo_greedy_phonemes.txt))
and the voice "Hải Đăng", Python
([`turbo_greedy_python.py`](turbo_greedy_python.py)) and Rust (test
`greedy_frames`) produce **the same 17 frames × 16 codec tokens**, stop
included: [`results/turbo_greedy_frames_python.txt`](results/turbo_greedy_frames_python.txt) =
[`results/turbo_greedy_frames_rust.txt`](results/turbo_greedy_frames_rust.txt).

This covers the whole inference path: prompt building, embeddings, the
speaker projection, backbone prefill/decode with its KV cache, the
16-codebook acoustic loop, the output heads and the stop token.

## 4. Nano with the same starting noise: the same waveform

Python ([`nano_fixed_noise_python.py`](nano_fixed_noise_python.py)) runs
with `seed=1234` and saves its starting noise; Rust (test
`fixed_noise_output`) starts from that noise:
[`results/nano_fixed_noise.txt`](results/nano_fixed_noise.txt). On the same
ONNX Runtime as Python (1.31): 34 560 samples, largest difference 7·10⁻¹⁰
(200 dB), practically bit-exact. On ONNX Runtime 1.28 (the one sherpa-onnx
links): 6.5·10⁻⁶ (111.6 dB), floating-point rounding.

## 5. Speech recognition (word error rate)

8 sentences ([`sentences.txt`](sentences.txt)) × 3 takes per engine, scored
with the sherpa-onnx Vietnamese recognizer `zipformer-vi-2025-04-20`
([`score_asr.py`](score_asr.py)); Python takes come from
[`python_reference.py`](python_reference.py). Full results, with every
misheard sentence: [`results/asr_wer.txt`](results/asr_wer.txt).

| Engine | Word error rate |
| --- | --- |
| Turbo, Python | 3.9% |
| Turbo, Rust | 1.9% |
| Nano, Python | 2.3% |
| Nano, Rust | 4.7% |
| Piper `vi_VN-vais1000-medium` (for reference) | 3.9% |

- "đi xa dần" heard as "đi xa" happens with every engine, Piper included:
  a recognizer error.
- The Python/Rust differences are sampling noise; sections 3 and 4 show
  the networks run identically. To make sure, the sentence Nano gets wrong
  most often ("Chúc bạn đọc sách vui vẻ.") was run 24 more times on each
  side: 4.2% for Python, 4.2% for Rust
  ([`results/asr_nano_24_takes.txt`](results/asr_nano_24_takes.txt)). The
  Rust noise generator was also checked on 10⁶ draws: mean −0.001,
  variance 1.000, kurtosis 2.99, lag-1 correlation −0.001 (test
  `dump_normals`).
- The Rust takes in that table were made with Marginalia's command line,
  which adds 1.5 s of silence at the end of a chapter; it was cut before
  scoring because the recognizer tends to "hear" words in long silence.
